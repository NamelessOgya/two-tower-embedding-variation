# Plan 019: テキスト埋め込みモデルのスケール検証レポート (mE5-small / base / large)

## 1. エグゼクティブサマリー

Plan 018 で最高精度を記録した **`TwoTowerLogQInfoNCE` ($\tau=0.07, \alpha=1.0$)** を標準学習アーキテクチャに据え、入力となる多言語テキスト埋め込みモデル `multilingual-e5` のスケール（**small: 384d / base: 768d / large: 1024d**）を変更した際の推薦性能への影響を系統的に検証した。

各スケールについて **5 つの独立シード（5 Seeds: 42, 43, 44, 45, 46）** で学習・評価を行い、単一推薦（Top-10）における精度とカタログ多様性を測定した。

## 3. 主要な知見とスケーリング則 (Key Findings)

### 💡 知見 1: モデルスケール拡大に伴う単調な精度向上（スケーリング則の成立）
- `small (384d)` ➔ `base (768d)` ➔ `large (1024d)` とモデルサイズをスケールアップするに従い、**すべての精度指標（Recall@10, Precision@10, NDCG@10, Hit@10）が単調に向上**した。
- `mE5-large (1024d)` は **全指標で最高スコア（Recall@10 = 0.02847, Precision@10 = 1.75%, NDCG@10 = 0.02392）** を達成した。

### 💡 知見 2: 表現力向上によるカタログ多様性とロングテール開拓の拡大
- 精度だけでなく、カタログ網羅率（`Coverage@10`）も `small (3.43%)` ➔ `base (4.24%)` ➔ **`large (5.16%)` と +50% 拡大**。
- ロングテールアイテムの網羅率（`Long-tail Coverage`）も `small (0.88%)` ➔ `base (1.07%)` ➔ **`large (1.63%)` と約 1.9 倍に拡大**。
- **メカニズム**: 言語モデルのパラメータ数と埋め込み次元数が増加することで、ユーザーの年齢・職業テキストと映画のニッチなジャンル・属性テキストの微細な意味境界（Semantic Boundaries）が明瞭に分離され、中位〜テールアイテムの適合推薦が促進される。

### 💡 知見 3: Small モデルの驚異的なコストパフォーマンス
- `mE5-small (384d, 118M)` はパラメータ数が large の約 1/5、埋め込み生成時間が 1/5 以下でありながら、**large の 95.1% の精度（Recall@10 = 0.02708）を維持**した。
- 高速な推論速度や省メモリ性が求められる実務・エッジ環境においては、`mE5-small` が極めて費用対効果の高い選択肢となる。

### 💡 知見 4: モデルスケールよりも学習手法（Log-Q InfoNCE）が圧倒的に支配的
- 埋め込みモデルのスケール拡大による精度差（small ➔ large で Recall が 0.02708 ➔ 0.02847、**+5.1% 向上**）に比べ、
- **学習手法の最適化（Base BPR ➔ Log-Q InfoNCE）による精度差（0.01020 ➔ 0.02831、**+177% / 2.8 倍向上**）の方が桁違いに大きい**。
- 実務において推薦精度を高めるためには、**「より巨大な言語モデルを使うこと」以上に「Two-Tower 学習時における Log-Q De-biasing の導入」が最優先課題である** ことが実証された。

---

## 4. 実務への提言 (Best Practices)

1. **最高精度を追求する場合**: `mE5-large (1024d)` + `Log-Q InfoNCE` の組み合わせが最高性能（Recall, Precision, Coverage 全てトップ）。
2. **実運用のバランス・標準構成**: `mE5-base (768d)` が精度・メモリ・計算速度の総合バランスで最も実用性に優れる。
3. **リソース制約・高スループット環境**: `mE5-small (384d)` を採用しても精度低下は 5% 未満に抑えられる。
